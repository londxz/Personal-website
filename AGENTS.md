# AGENTS.md

## Проект

Персональное IT-портфолио Родиона Холодова. Видимое название бренда — только `londxz`; домен `londxz.dev` допустим лишь как технический URL. Сайт должен выглядеть современно и профессионально, быстро загружаться, хорошо работать на телефонах и компьютерах и оставаться простым в поддержке.

Исходное подробное техническое задание обязательно учитывать целиком. Этот файл фиксирует его основные требования и последующие решения пользователя; более новые явные пожелания пользователя имеют приоритет.

## Согласованный стек

- React
- TypeScript
- Vite
- Tailwind CSS
- Motion только для небольших уместных анимаций
- Статический сайт без backend

Next.js, база данных, авторизация и тяжёлые библиотеки для первой версии не нужны.

## Визуальное направление

- Главный референс по атмосфере и композиции: `https://leonid.tatar`.
- Не копировать референс буквально. Создать узнаваемый стиль `londxz`.
- Взять за ориентир сильную desktop-композицию: заметная навигация, крупный Hero, сочетание текста и портрета/визуала, плавающие информационные badges, чёткая иерархия разделов.
- Основная визуальная версия — светлая: белый, молочный, графит и прозрачные оттенки серого. Тёмная тема остаётся дополнительной.
- Начальный язык интерфейса — русский; английский остаётся доступен через переключатель.
- Сохранять согласованную крупную композицию Hero со стеклянными слоями и плавающими плашками; при замене фотографии не менять масштаб и структуру всего дизайна.
- В Hero использовать только исходное фото пользователя `ava.jpg`. Фон удалять классической маской по исходным пикселям: без генеративной обработки, апскейла, ретуши лица, дорисовки деталей и нейросетевого сглаживания.
- Допустимо только обычное монохромное преобразование для согласованного визуального стиля. Перед публикацией проверять края волос, обоих ушей, плеч и рук крупным планом на белом и чёрном фоне; не допускать белого ореола и захваченных фрагментов фона.
- Не обрезать уши, волосы, руки и другие части человека. Не создавать искусственный контур, обводку или тяжёлый ореол вокруг него.
- Не растягивать портрет сильнее исходного качества: он должен занимать заметную правую часть Hero, но оставаться резким.
- Liquid glass — основной визуальный язык, а не единичный декоративный эффект. Использовать его в навигации, карточках, кнопках, badges, переключателях, блоках проектов и других интерактивных поверхностях.
- Стеклянные поверхности строить через прозрачность, `backdrop-filter`, многослойный blur, тонкие светлые границы, внутренние блики, мягкие тени, преломление света и едва заметную текстуру/noise.
- Под стеклом должны быть спокойные живые фоновые слои: световые пятна, мягкие монохромные градиенты и движение, благодаря которым blur действительно виден.
- Эффекты должны ощущаться дорогими и современными, но не ухудшать читаемость, контраст, скорость и управление с телефона.
- Анимации делать плавными и связанными с интерфейсом: появление секций, hover/tap, движение блика, небольшая реакция стекла на курсор и переходы темы.
- Для `prefers-reduced-motion` отключать параллакс, слежение за курсором и интенсивные переходы.

## Принципы разработки

- Делать собственный дизайн, не копировать референсы и готовые шаблоны.
- Не усложнять архитектуру без практической причины.
- Отделять редактируемый контент от компонентов.
- Использовать небольшие понятные компоненты и строгую типизацию.
- Поддерживать semantic HTML, клавиатурную навигацию, видимый focus и `prefers-reduced-motion`.
- Не добавлять секреты, токены и чувствительные личные данные во frontend или репозиторий.
- Сохранять хорошую производительность и минимальное количество клиентского JavaScript.

## Позиционирование

- Родион — сильный iOS-разработчик; Swift, UIKit и SwiftUI составляют основную экспертизу.
- AI и backend-разработка на Go — направления активного интереса и развития, без завышения уровня.
- CI упоминается только в конкретном опыте работы, но не подаётся как главная сильная сторона.
- Личные сильные стороны: высокая ответственность, умение брать задачу на себя и доводить до результата; результат — главный приоритет.

## Обязательный функционал из ТЗ

- Hero сразу объясняет, кто такой `londxz`, чем он занимается и куда можно перейти дальше.
- Navbar содержит Home, About, Skills, Projects и Contact, поддерживает плавную прокрутку и компактное mobile menu.
- About позволяет легко менять имя/никнейм, описание, местоположение, историю, интересы, направления обучения, цели и факты.
- Skills делятся на понятные категории и отображаются названиями, иконками и аккуратными badges/карточками.
- Карточка проекта содержит название, описание, preview, стек, статус, GitHub, Live Demo и при необходимости дату.
- Новые проекты добавляются изменением массива данных, а не основной разметки.
- GitHub заметно представлен, но недоступность GitHub API не должна ломать сайт.
- CV доступно по понятной кнопке; если файла пока нет, его можно добавить позже без переделки интерфейса.
- Contacts включает Telegram, GitHub и Email. Для Email предусмотреть копирование с уведомлением `Copied!`.
- RU/EN переключаются в интерфейсе; выбор языка сохраняется в `localStorage`. Допустимо начать с English, если архитектура сразу готова к Russian.
- Dark/Light переключаются в интерфейсе; выбор темы сохраняется локально.
- Footer содержит актуальный год, основные контакты и короткую подпись.
- Нужны собственные favicon, social preview и страница `404 — Page not found` с возвратом домой.
- Никакие чувствительные данные, домашний адрес, школа, личный телефон, ключи и токены не публикуются.

## Адаптивность и качество

- Проверить ширины 1920, 1440, 1024, 768, 390 и 375 px.
- Не допускать горизонтального скролла, обрезанного текста, слишком маленьких touch targets и сломанных карточек.
- Использовать semantic HTML, корректные заголовки, `alt`, `aria-label`, клавиатурную навигацию, видимый focus и достаточный contrast.
- Оптимизировать изображения в WebP/AVIF, задавать размеры, использовать lazy loading вне первого экрана.
- Не подключать тяжёлые зависимости ради эффектов, которые можно качественно сделать CSS и небольшим количеством JavaScript.
- Целевой Lighthouse Performance — не ниже 90, желательно 95+ без ущерба визуалу.
- Production build не должен содержать ошибок и предупреждений, которые можно разумно устранить.

## SEO и системные файлы

- Настроить `<title>`, description, canonical `https://londxz.dev`, Open Graph и Twitter/X metadata.
- Добавить качественное `og:image`, чтобы ссылка красиво выглядела в Telegram, Discord и других сервисах.
- Добавить `robots.txt`, `sitemap.xml`, favicon и статическую 404.
- Основной домен — `https://londxz.dev`; `www.londxz.dev` должен перенаправляться на него.

## Структура контента

Навыки, проекты, социальные ссылки, контакты и переводы должны храниться отдельно от визуальных компонентов, чтобы их можно было обновлять без изменения основной разметки.

Компоненты должны оставаться небольшими и понятными: `Navbar`, `Hero`, `About`, `Skills`, `Projects`, `ProjectCard`, `Contact`, `Footer` и вспомогательные UI-компоненты для glass-поверхностей.

Проект должен запускаться стандартно:

- `npm install`
- `npm run dev`
- `npm run build`

## Публикация

- Репозиторий GitHub хранит исходный код.
- Хостинг собирает и публикует сайт отдельно.
- Предпочтительный вариант публикации: Cloudflare Pages; GitHub Pages допустим как альтернатива.
- Push в production-ветку должен автоматически обновлять сайт.
- Основной публичный адрес: `https://londxz.dev`.

Сначала сделать сильный и законченный MVP. Дополнительные функции добавлять только после того, как основная версия выглядит хорошо и стабильно работает.
